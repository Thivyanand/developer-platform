# Contributing

This project is being built in public.

## Development philosophy

Prefer small, focused changes that are understandable, tested, documented when behavior or architecture changes, and safe to review.

## Commit style

Use conventional-style commit messages:

- feat: new functionality
- fix: bug fixes
- test: tests
- docs: documentation
- refactor: internal restructuring
- chore: tooling or maintenance

Example:

feat: add repository ingestion

## Pull requests

Every substantial feature should be developed on a feature branch and reviewed before merging into main.

## Safety

Never commit API keys, passwords, private credentials, personal access tokens, or production secrets.
